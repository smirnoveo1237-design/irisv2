# IrisV2

Многофункциональная экосистема для Telegram-групп: модерация, антиспам, профили, экономика
Ирисок, социальные связи, игры, аналитика, автоматизация и ИИ — в одном асинхронном боте.

**Главная особенность:** команды работают без обязательного `/`.

```
профиль      !профиль      .профиль      ирис профиль      /профиль
```

Разбор команд регистронезависимый, понимает лишние пробелы, аргументы и границы слов:
`профилька` не считается командой `профиль`. Префиксы настраиваются отдельно в каждой группе.

## Быстрый старт

1. Получите токен у [@BotFather](https://t.me/BotFather) и включите для бота режим privacy **off**
   (или выдайте права администратора в группе), иначе бот не увидит обычные сообщения.
2. Скопируйте конфигурацию:

   ```bash
   cp .env.example .env
   ```

3. Заполните минимум:

   ```dotenv
   IRIS_BOT_TOKEN=123456:AA...
   IRIS_BOT_USERNAME=IrisV2Bot
   IRIS_OWNER_IDS=ваш_telegram_id
   IRIS_SUPPORT_CHAT_ID=            # чат поддержки (необязательно)
   POSTGRES_PASSWORD=смените_меня   # для compose.yaml
   ```

4. Запустите:

   ```bash
   docker compose up -d --build
   docker compose logs -f bot
   ```

Контейнер сам ждёт PostgreSQL, применяет миграции Alembic и запускает long polling.
База и Redis поднимаются рядом, данные лежат в томах `pgdata` и `redisdata`.

5. Добавьте бота в группу и выдайте права: удаление сообщений, ограничение участников,
   закрепление (по желанию). Затем:

   ```
   ирис меню
   ирис настройки
   ```

### Деплой на Render (бесплатный тариф)

Бот поддерживает webhook-режим и готов к free web service Render: 512 МБ, 0.1 CPU,
750 часов/мес, health-check `/health`, миграции в entrypoint. Автопингер против сна —
[.github/workflows/keepalive.yml](.github/workflows/keepalive.yml). Пошаговая инструкция —
[docs/RENDER.md](docs/RENDER.md), blueprint — [render.yaml](render.yaml).

Коротко: загрузите папку `IrisV2` в GitHub → Render **New + → Blueprint** → заполните
`IRIS_BOT_TOKEN`, `IRIS_BOT_USERNAME`, `IRIS_OWNER_IDS`, `IRIS_DATABASE_URL` (Neon) → Deploy.
Бесплатный Postgres Render удаляется через 30 дней, поэтому нужен внешний PostgreSQL.

## Локальная разработка

### Самый быстрый запуск без Docker (SQLite)

Подходит, чтобы проверить бота на своей машине; для production нужен PostgreSQL.

```bash
python main.py --sqlite
```

Флаг `--sqlite` использует базу `./iris.db`, кэш в памяти и сам создаёт таблицы.
Ничего в `.env` менять не нужно; данные PostgreSQL при этом не затрагиваются.

Если хотите закрепить SQLite в конфигурации, замените в `.env` две строки:

```dotenv
IRIS_DATABASE_URL=sqlite+aiosqlite:///./iris.db
IRIS_REDIS_URL=
```

и запускайте `python main.py --create-db` (первый раз) / `python main.py`.

`python main.py` и `python -m app.main` — одно и то же; запускать нужно из корня
проекта `IrisV2`, а не из `app/`.

### Полноценный локальный запуск (PostgreSQL + Redis)

Требования: Python 3.12+, PostgreSQL 14+, Redis (необязательно), `pg_dump` для бэкапов.

```bash
python -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate
pip install -e ".[dev]"

# PostgreSQL можно поднять только сервисом db:
docker compose up -d db redis

cp .env.example .env               # укажите токен и IRIS_DATABASE_URL
alembic upgrade head

python main.py                     # запуск бота
python main.py --create-db         # dev-альтернатива миграциям (create_all)
```

Проверки:

```bash
python -m pytest -q
python -m ruff check app tests scripts
python scripts/dump_commands.py    # обновить docs/COMMANDS.md
```

## Как работает распознавание команд

Единый разбор находится в `app/commands/parser.py`, реестр — в `app/commands/registry.py`,
диспетчер — в `app/commands/executor.py` (вызывается из `IrisMiddleware`).

Порядок разбора:

1. Нормализация Unicode (`NFKC`), замена неразрывных пробелов, схлопывание пробелов.
2. Снятие ведущего `/`, префикса (`!`, `.`, …) или слова-триггера (`ирис`, `iris`).
3. Проверка границы: команда — это **целое первое слово**. `профилька` и `профильчик` не совпадут.
4. Для `/команда@BotName` проверяется, что упоминание адресовано IrisV2, а не другому боту.
5. Проверка, что имя есть в реестре, и что для «голого» вызова разрешён `allow_bare`.
6. Аргументы — весь остаток сообщения, с сохранением исходного текста (`raw_args`).

Правила, которые защищают от ложных срабатываний:

| Правило | Поведение |
|---|---|
| Границы слова | Сравнивается только первое слово целиком |
| Реестр команд | Незнакомое слово командой не считается |
| Лимит длины | «Голый» вызов длиннее `IRIS_MAX_BARE_LENGTH` (200) игнорируется |
| Флаг команды | Для опасных/шумных команд можно выставить `allow_bare=False` |
| Настройка группы | `bare_commands` и список `command_prefixes` хранятся в БД |
| `/` у другого бота | `/start@OtherBot` игнорируется |

Префиксы и триггеры хранятся в `chat_settings` и меняются командами:

```
ирис префиксы ! . $
ирис язык ru
```

## Реестр участников

Telegram Bot API **не отдаёт полный список участников группы** обычным ботам. Поэтому IrisV2
ведёт собственный реестр `chat_members`:

- любое сообщение участника (upsert по `chat_id + user_id`, счётчик сообщений);
- события `new_chat_members` и `left_chat_member`;
- администраторы чата, полученные через `get_chat_administrators` при необходимости;
- CAPTCHA-проверка помечает участника как подтверждённого.

Следствие: в старых группах реестр изначально неполный — он «догоняет» по мере активности.
Команды `шипперим` и `кто` при нехватке данных подтягивают администраторов и честно сообщают,
если участников всё ещё меньше двух.

## Две уникальные команды

### 💘 Шипперим

```
шипперим   !шипперим   .шипперим   ирис шипперим
```

- Кандидаты берутся из реестра участников, при нехватке — из администраторов чата.
- Другие боты исключаются, а сам IrisV2 — полноценный участник шутки (как в примере ниже).
- Один и тот же участник не может занять оба места (`random.sample`).
- Инициатор исключается, если после этого остаётся минимум два кандидата.
- Процентов и шкалы совместимости нет: только пара и случайная подпись.
- Ссылки: `https://t.me/username`, а если username нет — `tg://user?id=…`.
- Последние 12 пар группы хранятся в `shipper_pairs`; выбор до 12 раз пытается не повторяться.
- Задержка настраивается в каждой группе: `шипперим задержка 60` (секунды, `0` — выключить).
  По умолчанию 30 секунд; настройка видна в `ирис настройки`.

Пример ответа:

```
💞 РАНДОМ ШИППЕРИМ: Ванлулу (https://t.me/skitel55) + IrisV2 (https://t.me/iristr5plbot).
Любите друг друга и берегите. Мур.
```

Логика вынесена в `app/modules/shipper/service.py` и покрыта тестами без Telegram.

### 🔮 Ирис кто

```
ирис кто самый смешной
кто самый умный
!кто сегодня женится
.кто главный мем
```

- Случайный реальный участник; боты и IrisV2 исключены.
- Весь текст после «кто» сохраняется дословно (до 200 символов) и подставляется в ответ.
- Случайные фразы: «Я думаю, что …», «Шар говорит, что …», «Мне кажется, что …»,
  «Моя интуиция подсказывает, что …», «Вселенная выбрала …» и ещё две.
- Кнопка «Ещё раз» перебрасывает участника, сохраняя исходный вопрос.

## Экономика Ирисок

- Валюта: **Ириски**; кошелёк привязан к паре `(chat_id, user_id)` — данные групп не смешиваются.
- Стартовый бонус новому кошельку — 100 Ирисок.
- Все операции идут через `EconomyService` и журнал `transactions`.
- Атомарность: кошельки блокируются `SELECT … FOR UPDATE` в детерминированном порядке
  (защита от дедлоков), списание проверяет баланс до записи, в БД есть `CHECK (balance >= 0)`.
- Идемпотентность: `transactions.idempotency_key` уникален; повторная операция с тем же ключом
  бросает `DuplicateOperation` и не меняет баланс. Ключи используются для бонуса, покупок,
  наград за квесты/игры/автоматизации.
- Ежедневная награда: базовая 50 + 10 за каждый день серии, максимум ×3; серия сбрасывается
  при пропуске дня; повторный вызов в тот же день возвращает «уже получено».

## ИИ

Провайдеры опрашиваются по цепочке, пока один не ответит:

1. **Groq** — `GROQ_API_KEY`, `GROQ_API_KEY_2`, модели `GROQ_MODEL` / `GROQ_MODEL_FALLBACK`;
2. **OpenRouter** — `OPENROUTER_API_KEY`, `OPENROUTER_API_KEY_2`, модель `OPENROUTER_MODEL`;
3. **TokenHarbor** — `TOKENHARBOR_API_KEY`, `TOKENHARBOR_MODEL`;
4. **Pollinations** — бесплатный фоллбэк без ключа, `POLLINATIONS_MODEL`;
5. **Gemini** — `GEMINI_API_KEY`, список `GEMINI_MODELS` через запятую.

Ключи задаются в `.env`; для совместимости принимаются имена с префиксом `IRIS_`.
Старые `IRIS_AI_BASE_URL` / `IRIS_AI_API_KEY` / `IRIS_AI_MODEL` работают как последний
custom-провайдер, если новых ключей нет.

Команды:

```
.gpt кто ты?            # явная команда, работает независимо от переключателя чата
gpt как включить капчу?
ирис как дела?          # обращение к боту без команды
ии объясни шипперим    # старый алиас
объясни шипперим       # объяснение конкретной команды
```

Переключатель «ИИ» в `ирис настройки` управляет пассивными ответами; явный `.gpt`
отвечает всегда, пока ИИ включён на сервере (`IRIS_AI_ENABLED=true`).

Что умеет: отвечать на вопросы, объяснять команды, придумывать приветствия, суммировать
обсуждение (если включена история `ai_history_enabled`).

Чего **не** делает: не выполняет административные действия, не вызывает инструменты и не
обещает «забанить за вас». В системном промпте это зафиксировано, а в коде у ИИ нет доступа
к сервисам модерации. Если все провайдеры недоступны, бот отвечает понятным сообщением,
а не падает; ключи в логи не попадают.

TokenHarbor на бесплатных моделях требует включить data sharing в личном кабинете —
иначе шлюз отвечает `403 free_models_disabled`, и бот идёт к следующему провайдеру.

## Архитектура и структура

```
IrisV2/
├── app/
│   ├── main.py                 # запуск, Dispatcher, polling, graceful shutdown
│   ├── container.py            # DI-контейнер: сервисы на сессию
│   ├── core/                   # settings, logging, db, cache, texts, timeutil, middleware
│   ├── database/
│   │   ├── base.py             # DeclarativeBase, BigInteger-вариант для SQLite
│   │   ├── models/             # 42 таблицы по доменам
│   │   └── utils.py            # диалект-независимый UPSERT
│   ├── commands/               # parser, registry, context, middleware, router
│   ├── services/               # экономика, модерация, антиспам, уровни, ИИ, квесты…
│   ├── modules/                # 17 модулей: handlers.py + service/panels
│   └── ui/                     # общие клавиатуры и рендер колбэков
├── tests/                      # 100+ тестов (unit + интеграция через feed_update)
├── migrations/                 # Alembic: env.py + начальная ревизия
├── docker/entrypoint.sh
├── scripts/                    # wait_for_db, backup, init_db, seed_demo, dump_commands
├── compose.yaml
├── Dockerfile
└── pyproject.toml
```

Поток обработки сообщения:

```
Telegram → Dispatcher
  → ContainerMiddleware (внедряет зависимости)
  → IrisMiddleware
      1. upsert пользователя, группы, участника (реестр)
      2. суточная статистика, опыт, квесты
      3. антифлуд/антиспам → наказание и остановка
      4. разбор команды → command_ctx
  → commands.executor (проверка прав, кулдаун, вызов обработчика)
  → роутеры модулей (FSM, игры, ИИ, поддержка)
  → commit / rollback, закрытие сессии
```

Подробнее: [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md).

## Безопасность

- Токен и ключи — только в переменных окружения / `.env`, который не коммитится.
- Все запросы к БД параметризованы SQLAlchemy; «сырого» SQL с подстановкой нет.
- Права проверяются перед каждым административным действием: владелец бота, создатель чата,
  администратор Telegram (с учётом конкретных прав) или пользовательская роль IrisV2.
- Проверяются права **бота**: если нет `can_restrict_members` / `can_delete_messages`,
  бот не пытается выполнить действие и объясняет причину.
- Цель наказания проверяется: нельзя себя, бота, другого администратора (кроме владельца бота).
- Кулдауны команд и лимиты переводов; идемпотентность финансовых операций.
- Данные групп изолированы по `chat_id` во всех запросах.
- Структурированные логи (JSON в production), ошибки не роняют polling.
- Аудит действий и журнал модерации; уведомления в лог-канал.

`Update → middleware → команда → БД` через `Dispatcher.feed_update`.

Тесты используют SQLite в памяти (`StaticPool`), поэтому не требуют PostgreSQL и сети.

## Резервные копии

```bash
python scripts/backup.py --keep 14
# или разово через compose:
docker compose --profile tools run --rm backup
```

`pg_dump` в формате custom; восстановление:

```bash
pg_restore --clean --if-exists -d iris backups/iris_20261122_120000.dump
```

Храните копии вне сервера с ботом — локальный диск не спасёт от потери машины.

## Ограничения и честный статус

Реализовано и проверено тестами: ядро, БД, все 17 модулей, все 70 команд, экономика,
модерация, антиспам, две уникальные команды, меню, настройки, миграции, Docker.

Осознанные ограничения:

- **Реестр участников неполный по вине Telegram API.** Бот не может получить весь список
  участников; «старые» группы наполняются постепенно.
- **Long polling, один процесс.** Кэш настроек живёт в процессе 30 секунд; при нескольких
  воркерах изменения настроек могут применяться с задержкой. Для нескольких процессов нужен
  Redis (он уже поддерживается) и внешний планировщик.
- **CAPTCHA** ограничивает новые сообщения через `restrict_chat_member`; если у бота нет прав
  на ограничение, проверка не сможет удержать новичка.
- **Удаление истории** (`очистить N`) удаляет диапазон ID сообщений и может пропустить
  недоступные сообщения — Telegram не даёт боту читать произвольную историю.
- **Квесты и турнир** считаются по суточным счётчикам (`user_day_stats`), а не по внешней
  аналитике; набор квестов по умолчанию — 3 ежедневных.
- **ИИ** требует внешнего API-ключа и не выполняет административных действий.
- **Голосования** — собственные кнопки IrisV2, а не нативные Telegram-опросы.
- **Локализация**: интерфейс, меню и основные ответы переведены RU/EN; часть игровых
  текстов и подсказок остаётся на русском. Валюта в EN-локали называется «Iris coins».
- **Аукционы, каталог сообществ и сезонные события** из ТЗ не реализованы: экономика
  закрыта магазином, переводами и наградами, турнир недели есть, а для аукционов и каталога
  нужен отдельный модераторский процесс и UI. Это следующие кандидаты на развитие.
- Платёжный шлюз для покупки Ирисок не подключён: экономика замкнута внутри бота.

Дальше логично добавить: вебхуки и горизонтальное масштабирование, нативные опросы,
сезонные события с наградами, экспорт аналитики в CSV, Prometheus-метрики и веб-панель.
